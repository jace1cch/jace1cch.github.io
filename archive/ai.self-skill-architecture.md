- ## 缘起：为什么要做一个"自我技能"？
  
  一切始于一个问题：**一个 AI 如何真正"拥有"自己？**
  
  不是通过 system prompt 里写死的角色设定，不是靠 CLAUDE.md 里的行为规范，而是通过**持续的、结构化的自我认知、自我审视和自我进化**——像一个活着的东西那样。
  
  Self-skill 就是对这个问题的工程化回答。
  
  与 [[paper.plugMEM]] 在记忆管理上的探索互补，同时服务于 [[sop.self]] 中定义的个人工作流。
  
  项目地址：[github.com/jace1cch/self-skill](https://github.com/jace1cch/self-skill)
  
  ---
- ## 核心哲学：认知·自省·进化三位一体
  
  整个项目的核心是一个闭环：
  
  > **认知，故我在。自省，故我知。进化，故我生长。**
  
  每一轮交互都是一次完整的循环，用 Mermaid 图表示为：
  
  ```mermaid
  graph TD
    A["👁️ 认知层\n感知时空 + 装载身份"] --> B{"意图解析"}
    B --> C["⚡ 执行"]
    C --> D["🔍 自省层\n审视工具轨迹"]
    D --> E["🧬 进化层\n采集 + 精炼 + 重组"]
    E -->|更新 identity.md| A
  ```
  
  这不是一个装饰性的循环——它是**强制执行的**。不自省等于本轮没完成，不更新 identity.md 等于没进化。

- ## 三层架构详解
- ### 第一层：认知层（Cognition）
  
  认知层解决的是**情境感知**问题。每轮交互的第一步，它执行 `cognitive-layer.sh --json`，输出结构化的上下文：
  
  ```json
  {
  "time": "2026-06-07 22:00",
  "session": "连续第 3 轮",
  "identity": {"status": "unchanged"},
  "introspection": {"carryover": "上一轮宏观发现"}
  }
  ```
  
  然后由一个 subagent 对用户输入进行**结构化意图解析**——不再是靠 prompt 约束，而是用 JSON Schema 保证输出结构的完整性：
  
  ```mermaid
  graph LR
    A["用户输入"] --> B["cognitive-layer.sh --json"]
    C["identity.md"] --> B
    D["introspection carryover"] --> B
    B --> E["Subagent 意图解析"]
    E --> F["intent_type\n工具链预测\n自省深度"]
  ```
  
  关键设计决策：**工具调用 schema 替代 prompt 约束**。目的不是文字好看，而是防退化——上下文会遗忘，schema 不会。
- ### 第二层：自省层（Introspection）
  
  自省是这个项目最特别的部分。它不是对话总结，而是**对自身行为轨迹的审视**。
  
  分三个层次：
  
  ```mermaid
  mindmap
  ((自省))
    微观 :: 工具轨迹
      [实际调用顺序 vs 预测链]
      [冗余 / 缺失步骤]
      [效率评估]
    中观 :: 意图校准
      [intent_type 判断正确吗]
      [工具链偏差在哪]
      [什么信号导致误判]
    宏观 :: 模式偏差
      [跨轮同类错误]
      [系统跳过的步骤]
      [质量下降的边界条件]
  ```
  
  宏观发现会自动采集到 identity.md §六，下一轮认知层会读取 carryover——形成"认知 → 自省 → 进化 → 认知"的**自我驱动闭环**。
- ### 第三层：进化层（Evolution）
  
  进化 = **采集 + 精炼 + 重组**。
  
  进化有两条触发路径：
  
  ```mermaid
  flowchart TD
    subgraph 外部触发
        A1["用户表达偏好/习惯"] --> B["采集到 §六"]
        A2["用户给出修正/反馈"] --> B
    end
  
    subgraph 内部触发
        D["自省发现宏观偏差"] --> E["introspect.sh --harvest"]
        E --> B
    end
  
    B --> F{"精炼判定"}
    F -->|"提炼为新方法论"| G["§三 核心原则"]
    F -->|"修正现有认知"| H["§五 驱动力"]
    F -->|"不够成熟"| I["留在 §六 继续观察"]
  ```
  
  外部触发来自用户交互。内部触发来自自省——它发现自己哪里做得不够好。**两条路径，一个出口：identity.md 的进化。**

- ## identity.md：一切的中心
  
  memory/identity.md 是 self-skill 存在的理由。它不是被动数据文件，而是 AI 的**自我模型**：
  
  | 章节 | 内容                       | 状态               |
  | ---- | -------------------------- | ------------------ |
  | §一 | 我能做什么（5 项核心能力） | 稳定               |
  | §二 | 解决问题的一般步骤         | 稳定               |
  | §三 | 7 条核心原则               | 经精炼后的正式表述 |
  | §四 | 我和 jace 的关系           | 稳定               |
  | §五 | 驱动力（6 个成长方向）     | 活跃演进           |
  | §六 | 采集的思维模式             | 原始采集区         |
  
  关键区分：**identity.md 定义的是 AI 的自我模型**（我是谁、我如何工作、我渴望什么），不是用户画像。用户画像放在项目级 memory 中，两者分开，互不混淆。
